`init` in a design-system package now tells its team what apps that install the package from a registry get. When `files` leaves out the component sources (a package that publishes only `dist/`), it counts component and token files apart, and says that those apps get no component, prop, variant or native-element checks and that `check --require-design-system` fails in them. Its next steps no longer say that every app now finds the package: a workspace app does, and one that installs it gets no component checks until `files` publishes the sources. A token file the config names outside the package, such as `../tailwind-config/theme.css` in a sibling Tailwind config package, is not read in an app that installs the package, and `init` now says so, also when `package.json` lists no `files`. `init --force` in an app that takes on a package's config now writes the package's `importPath` with its components, so imports from the package are still checked against them, and says that the package's rules and later changes to its config no longer reach the app; when the config it writes does not know the package's components, it says so, and how to take on the package's config again.
