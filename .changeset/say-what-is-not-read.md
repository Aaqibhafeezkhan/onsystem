`check`, `check_ui` and `inspect` now say what they could not read. An app built on Chakra UI or Mantine, with no components of its own, got "No problems" and the generic "No design system found" notice, which pointed to the configuration docs: nothing said that onsystem does not read those libraries yet. When a project without components of its own depends on Chakra UI (`@chakra-ui/react`), Mantine (`@mantine/core`), HeroUI (`@heroui/react`), Radix Themes (`@radix-ui/themes`) or Ant Design (`antd`), `check` and `check_ui` now add a notice that names the library, says that only MUI is read so far, and suggests wrapping its components in your own; `check --require-design-system` prints it with the failure. `inspect` lists each such library on its `library` line, and `inspect --explain` under how the design system was found. Without `node_modules`, the props of components that wrap other packages do not resolve and `no-unknown-prop` skips those components: the demo checked before `npm install` gave 7 errors instead of 8, with nothing to say why. `check` and `check_ui` now add a notice when the dependencies a project declares are not installed, with how many components `no-unknown-prop` skips, and plain `inspect` prints it on stderr. At a monorepo root, one notice names every project it applies to. Neither notice changes the exit code or the findings.
