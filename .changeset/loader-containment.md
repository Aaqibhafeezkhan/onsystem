'onsystem': patch
---

The design system's component, token and docs files are read only when their real path, links resolved, is in the project, the workspace or git repository it is in, or a package installed in `node_modules`. A cloned repository could have `get_component` return any file on the machine: a component named `Credentials` and a committed link `components/ui/credentials.md` to `~/.aws/credentials` put that file in the component's description, with zero config and also in a project the server found from a tool call's path, where it reads only JSON configs. So did `docs` or `tokens` in `onsystem.config.json` naming an absolute or `../` path, and a token stylesheet that `@import`s a linked one. Such files are now skipped, and `inspect` and the server's log name them: `Not read: components/ui/credentials.md leads outside the project.` Workspace packages (`../../packages/ui`), pnpm's links into its store and design-system packages that declare their config read as before. A package linked from elsewhere on the machine without a declared config (`npm link`) is no longer read: make it a workspace package, or run `onsystem init` in it. A file found through two paths, such as through a folder that links back to its parent, is read once, and `check` lints it once.
