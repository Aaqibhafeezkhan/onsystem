The Claude Code hook now honours the config and baseline at a monorepo root. `init` at the root writes both, and `check .` there reads them, but the hook ran `check` from the edited file's project folder (the nearest `package.json`), where neither is read: it blocked Claude on findings the root baseline accepts, whenever Claude wrote a whole file, and on rules the root config turns off, on any edit. When the nearest workspace root has an onsystem config or baseline, the hook now runs the check from there, so a file is checked as `check .` at the root checks it: by its own project, with the root's rules and baseline. A project that keeps a baseline of its own, as a CI job per app does, is still checked from its own folder, and a project's own install of onsystem is still the one that runs. The hook now passes the file to the CLI relative to the folder it runs in, so that from the root, a path through a symlink (macOS's `/tmp`) still lands in the file's project.
