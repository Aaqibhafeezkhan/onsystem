`init` in a shadcn/ui app now adds to `components`, next to `components/ui`, the folders `npx shadcn add` copies other registries' code into: for each registry in the `registries` of `components.json`, the folder of that name under the `components` alias (`@signoff-ui` → `components/signoff-ui`, `@ai-elements` → `components/ai-elements`). A folder with no `.tsx` or `.jsx` file yet is added too, and so is one that does not exist yet: a registry is often named in `components.json` before its first `shadcn add`, and an item of only `.ts` files, such as signoff-ui's `ag-ui`, makes the folder before a component lands in it. `check`, the Claude Code hook, the dry run and the baseline skip that code as they skip `components/ui`, so the next `shadcn add` no longer brings findings in registry files nobody edited, and the app's code is checked against every component those files export, helpers included. `init` names each folder it added, with a link to how to leave the helpers out or check that code as your own. When it cannot add them (`--components` given, or an `importPath` that names a package), it says that `check` reads that code as the app's own, and names the glob that sets it apart: for `components`, or, when the config imports its components by a package name, for an `overrides` entry that turns the rules off. Code a registry puts loose in `components/`, as React Bits does, is still checked as the app's. Configs written before are not changed.
