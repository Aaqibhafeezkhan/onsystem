'onsystem': patch
---

The Claude Code hook no longer waits for the npm registry on every edit. In a project without its own install, it ran `npx --yes onsystem@<version>`, and npx asks the registry about the package on every run, even with the exact version in its cache: offline, each `.tsx` or `.jsx` edit waited 55 seconds and was still not checked. The hook now runs `npx --prefer-offline`, which uses the cached package without asking the registry, so it checks offline too and makes no request once the package is cached. If npm itself fails with its cache, as when npm's cached list of versions predates a new plugin release, the hook runs once more with `--prefer-online`; a failure of the CLI, such as an invalid config, is reported at once, without a second run. When npx does not finish within 55 seconds, the notice now adds that npm may not have reached the registry (offline?). When npm could not reach the registry, or npx did not finish in time, the hook does not start npx again for ten minutes in that session, so an offline session waits once instead of on every edit. A project install (`npm install --save-dev onsystem`) runs as before. The plugin docs no longer say that npx only reaches the network the first time: the MCP server's npx asks the registry each time it starts.
