`no-hardcoded-color` reads tokens whose names start with `on-` (Material's) as text colors, and those that start with `content-` (Dub's) too, unless the name goes on to say border or background (`content-border`, `content-background`). `text-neutral-400` now matches Dub's `content-muted`, and `border-*`, `ring-*` and `bg-*` classes are no longer fixed to a text color. When the only close token is made for another role, the message names it ("content-subtle has this color, but it is meant for text") instead of saying that no token is close. A Tailwind palette class is now fixed only to a token that matches it (ΔE under 0.02), or to one that is nearest the class's own shade and within ΔE 0.037 of it, the most Tailwind v3 and v4 differ on one shade, so tokens that copy v3's palette (`text-red-600` to a token holding v3's red-600) keep their fix. Other close tokens are still suggested, without a fix, so `eslint --fix` leaves them, and the message says why and what to do: `content-default` for `text-neutral-600` is one shade darker (neutral-700), and a token at neutral-500 for `text-slate-500` is closest to neutral-500, not slate-500.
