'onsystem': minor
---

Zero config now reads a design-system package installed from a registry when it is named like one (`@acme/ui`, `@acme/design-system`) and its `exports` lead to the `.tsx` or `.jsx` sources it publishes, as it reads a workspace package, with no config in the app or the package. Before, such an app got no components and no tokens: a package that publishes `src/`, such as one whose `exports` point at `./src/index.ts`, was skipped as compiled. Its exported stylesheets are its tokens, with the ones of the package they `@import`, and an app stylesheet's `@import "@acme/ui/globals.css"` is followed into `node_modules` when the app's config names no `tokens`. Other installed packages, such as `tailwindcss`, are not read. With pnpm the package is read in `node_modules/.pnpm`, so the props its components take from their own dependencies resolve. A package that publishes build output alone is still not read, and `inspect --explain` now says why: `it publishes build output (node_modules/@acme/ui/dist/index.mjs) and no component source`, instead of calling every installed package compiled. An app whose own config leaves `components` unset now picks up such a package too.
